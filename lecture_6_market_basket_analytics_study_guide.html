1. Market Basket Analysis Overview

Modeling technique based on the theory that if you buy a certain group of items, you are more likely to purchase another group of items (e.g., peanut butter and bread implies jelly).

Terminology: Association Rule Learning is general; Market Basket Analysis is retail-specific; Affinity Analysis is broader.

2. Itemsets & Transactions

Let $I = \{i_1, \dots, i_n\}$ be a set of items. Subsets of $I$ are called itemsets.

$T = \{ (t_i, B_i) \mid t_i \in \mathbb{N}, B_i \subseteq I \}$
Rule: $X \Rightarrow Y$ where $X, Y \subseteq I$

Transactions $T$ represent customer purchases where baskets $B_i$ contain subsets of items.

3. Support, Confidence & Lift

  • Support: Ratio of transactions containing $X$: $$\text{support}(X) = \frac{|\{t_i : X \subseteq B_i\}|}{|T|}$$
  • Confidence: Probability of $Y$ given $X$: $$\text{conf}(X \Rightarrow Y) = \frac{\text{support}(X \cup Y)}{\text{support}(X)}$$
  • Lift: Strength over independence: $$\text{lift}(X \Rightarrow Y) = \frac{\text{conf}(X \Rightarrow Y)}{\text{support}(Y)}$$

4. The Apriori Algorithm

Iteratively mines frequent itemsets by leveraging the Apriori property: if an itemset is frequent, all its subsets must also be frequent.

  • Generate candidate itemsets $C_k$ from $L_{k-1}$.
  • Filter by minimum support threshold to get $L_k$.

5. FP-Growth (Faster Mining)

Addresses performance bottlenecks of Apriori by avoiding repeated database scans and candidate generation.

  • Constructs a compact FP-Tree (Frequent Pattern Tree).
  • Uses divide-and-conquer conditional pattern bases.

Tool 2: Apriori Candidate Generation vs FP-Tree Simulator

Compare candidate itemset explosion in Apriori versus compact tree compression in FP-Growth.

Apriori Algorithm Characteristics

  • Approach: Level-wise iterative candidate generation ($C_k$ from $L_{k-1}$).
  • Database Scans: Requires multiple full scans of database for support counting.
  • Bottleneck: Generates massive candidate sets when minimum support is low.

FP-Growth Algorithm Characteristics

  • Approach: Divide-and-conquer frequent pattern tree construction.
  • Database Scans: Only 2 database scans required.
  • Advantage: Compresses transaction database into FP-Tree, avoiding candidate generation.
